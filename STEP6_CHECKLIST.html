צ'קליסט צעד 6 — הפעלת ה-waitlist (הפעולות שדורשות את חשבון הגוגל שלך)

עודכן: 12.08.2026. הקוד כולו מוכן; נשארו רק פעולות בחשבונות שלך.
הקבצים: site/index.html (דף הנחיתה לייצור) · apps-script/Code.gs (הבקאנד).

0. חשבון גוגל ייעודי לפרויקט (הוחלט 12.08.2026 — לעשות לפני הכול)

יוצרים חשבון Google חדש ייעודי (למשל everyvest.app@gmail.com — אחרי הכרעת השם, כי שם החשבון כדאי שיתאם את המוצר), ומפעילים עליו אימות דו-שלבי. כל מה שבצ'קליסט הזה — ה-Sheet, ה-Apps Script, נכס ה-GA4 וההרשמה ל-Netlify — נפתח מתוך החשבון הזה, לא מהחשבון האישי. למה עכשיו: העברת בעלות על Apps Script deployments ונכסי GA4 אחר כך היא כאב ראש; מייל עתידי ללקוחות ממילא חייב לצאת מכתובת עסקית (כלל "לא שולחים מהג'ימייל הפרטי" שבמדריך); וזה מפריד את הדאטה של הנרשמים מהחשבון הפרטי.

א. Google Sheet + Apps Script (כ-10 דקות)

  1. פתח קובץ Google Sheets חדש, קרא לו everyvest-waitlist. שנה את שם הגיליון (הטאב למטה) ל-waitlist.
  2. העתק את ה-SPREADSHEET_ID מכתובת הדפדפן — החלק שבין /d/ לבין /edit.
  3. בתפריט: תוספים ← Apps Script. מחק את הקוד הקיים ב-Code.gs והדבק את התוכן של apps-script/Code.gs מהפרויקט.
  4. בשורה הראשונה החלף את PASTE_YOUR_SPREADSHEET_ID_HERE ב-ID שהעתקת. שמור (Ctrl+S).
  5. הרצה חד-פעמית: בחר בתפריט הפונקציות את setupWaitlistSheet ולחץ Run. אשר את ההרשאות (יופיע מסך "Google לא אימתה" — מתקדם ← המשך). בגיליון תופיע שורת הכותרות: Timestamp, Username, Email, Interest.
  6. פריסה: Deploy ← New deployment ← סוג: Web app ← Execute as: Me ← Who has access: Anyone ← Deploy. העתק את כתובת ה-Web App (מסתיימת ב-/exec).
  7. ב-site/index.html החלף את YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL בכתובת שהעתקת.
  8. בדיקה: פתח את כתובת ה-Web App בדפדפן — אמור להופיע {"success":true,"service":"Everyvest Waitlist API"}.

הערה לעתיד: אחרי כל שינוי בקוד ה-Apps Script — Deploy ← Manage deployments ← עיפרון ← Version: New version ← Deploy (לא ליצור deployment חדש, כדי שהכתובת לא תתחלף).

ב. GA4 (כ-10 דקות)

  1. https://analytics.google.com ← יצירת נכס Everyvest (אזור זמן ישראל).
  2. פלטפורמה: אתר ← הדבק את כתובת האתר (אחרי הפריסה בסעיף ג') ← קבל Measurement ID שמתחיל ב-G-.
  3. ב-site/index.html החלף את שתי ההופעות של G-XXXXXXXXXX ב-ID שלך.
  4. אחרי עלייה לאוויר: ניהול ← תצוגת נתונים ← אירועים ← סמן את sign_up_waitlist כאירוע מפתח (Conversion).
  5. בדיקת זמן אמת: דוחות ← סקירה בזמן אמת ← בצע הרשמת ניסיון ← ודא שהאירוע נספר וששורה נוספה בגיליון.

ג. פריסה (כ-5 דקות)

  • הכי פשוט: Netlify — גרור את תיקיית site/ ל-app.netlify.com (Deploy manually), או חבר ריפו GitHub.
  • אופציונלי: Site configuration ← Change site name לכתובת נאה (למשל everyvest.netlify.app).
  • אחרי שינוי ה-URL ב-GA4 (סעיף ב-2) — לוודא שהכתובת הסופית היא זו שהוזנה.

ד. בדיקת קצה-לקצה (חובה לפני הפצה)

  1. הרשמה בדף החי ← שורה חדשה בגיליון + אירוע ב-GA4 Realtime.
  2. הרשמה עם אותו מייל שוב ← לא נוספת שורה כפולה (הטופס עדיין מציג הצלחה — זה מכוון).
  3. שני טאבים במקביל ← שתי שורות נפרדות (LockService).
  4. מובייל אמיתי: נטען מהר, ה-CTA הדביק עובד, הטופס נשלח.

מה כבר מטופל בקוד (לא צריך לגעת)

  • כפתור נחסם בזמן שליחה ואחרי הצלחה (מניעת רישום כפול מהצד שלנו).
  • מניעת דובלים לפי מייל בצד השרת + LockService נגד תנאי מרוץ.
  • honeypot נגד בוטים, ולידציה בשני הצדדים, הגנה מהזרקת נוסחאות לגיליון.
  • אירוע sign_up_waitlist נשלח ל-GA4 כולל פילוח ה-interest.
  • שאלת הפילוח ("מה הכי חשוב לך?") נשמרת בעמודת Interest — זה המדיד של פיצול הקהלים.
